# 行为规格 v0.1（历史基线）

> 本文档描述早期实现假设。当前工程实现以 `docs/系统需求规格_v0.3.md` 和领域模型文档为准；未被新需求覆盖的条目继续有效，但仍需由代码和测试验证。

## 规格来源

本规格来自柔性引擎/本体化设计分析、20 条契约定义、历史测试报告和论文论点材料。它描述的是独立平台的目标行为，不等同于任何外部生产系统内部实现。

## 明确行为

1. 动态字段必须可以按名称、类型、必填性和版本进行校验。
2. 动态记录必须支持固定顺序的字段输出，便于实验结果重现。
3. 工作流只能沿已声明的状态转换移动；非法事件必须失败。
4. 上下文快照必须具有稳定哈希；同一内容不因 Map 插入顺序改变而改变哈希。
5. Questionnaire、Subject、Option 形成可遍历关系。
6. `JobOntologyDetail` 同时保存固定属性、动态属性和关系。
7. 兼容层必须显式处理正常、空值、兼容和非法输入。

## 当前假设

- 空的 subject 查询代表“无筛选查询”，返回当前仓库中的全部套卷；该行为作为平台的明确实现假设，后续由契约版本更新替换。
- 保存关系配置必须是幂等的；相同配置重复保存不能产生重复关系。
- 平台使用本地注册表承载 Provider/Consumer 兼容调用，不依赖远程 JSF 注册中心。
