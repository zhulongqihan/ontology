# 柔性引擎与本体化平台系统需求规格 v0.3（产品定位修订版）

更新时间：2026-09-02
状态：工程基线，作为后续实现的需求入口

## 1. 目标与边界

本系统的主目标是从零构建一个可运行、可配置、可审计的柔性引擎与本体化平台。系统以动态 Schema、事件驱动流程、本体对象关系和兼容服务为核心能力，提供从模型定义到运行审计的完整闭环。

后台控制面是引擎的操作入口，必须改变真实的引擎配置和运行状态。静态页面、预置数字和仅存在于浏览器内存中的状态不能作为正式功能。

系统分为两条边界清晰的链路：

1. 引擎链路：模型、Schema、工作流、本体、服务、上下文、运行和 Trace。
2. 实验链路：契约用例、回归执行、报告、哈希、证据和论文导出。

实验链路可以调用引擎链路，但不能反向把实验结果硬编码进引擎状态。

## 2. 功能需求

### 2.1 模型注册

- 注册唯一模型 ID、名称、说明和生命周期状态。
- 每个模型拥有独立的 Schema、工作流和本体绑定。
- 模型配置必须有版本号和变更记录。
- 不允许删除仍被运行上下文引用的模型版本。

### 2.2 动态 Schema

- 支持 STRING、INTEGER、DECIMAL、BOOLEAN、JSON、OBJECT。
- 字段具有名称、类型、必填性、默认值和版本。
- Schema 发布后不可原地修改，只能创建新版本。
- 支持字段新增、改名、删除和默认值迁移。
- 运行记录必须固定使用当次的 Schema 版本。

### 2.3 工作流

- 工作流由初始状态、状态节点和事件转换组成。
- 同一状态下同一事件只能对应一个转换。
- 未声明事件必须失败且不得改变状态。
- 运行上下文可以从已保存状态恢复。
- 状态迁移必须记录前状态、事件、后状态和 Trace。

### 2.4 本体模型

- 注册本体类型、固定属性和动态属性。
- 注册来源类型、目标类型、关系名和基数。
- 运行时将柔性对象装配为本体对象。
- 目标类型不存在、关系重复或基数不满足时必须产生可解释错误。

### 2.5 服务兼容层

- 服务具有 ID、Provider、Endpoint、版本和状态。
- 本地服务必须明确使用 `local://` 地址。
- Provider 调用必须记录请求、响应、错误、耗时和 Trace。
- 真实生产注册中心不可用时，不能伪装为生产服务在线。

### 2.6 运行上下文

- 运行上下文具有唯一 `contextId`。
- 同一上下文可以多次执行事件。
- 每次执行固定模型版本、Schema 版本和工作流版本。
- 支持成功、失败、重试、回滚和回放。
- 相同幂等键的重复请求不能重复推进状态。

### 2.7 可观测与审计

- 每次运行必须有 `runId`、`traceId`、开始时间、结束时间和耗时。
- Trace 至少拆分请求、校验、工作流、本体、Provider、持久化和响应阶段。
- 配置变更必须写入审计事件。
- 审计事件必须保留稳定的字段路径及 before/after 值，不能只依赖自然语言描述。
- 运行输入、输出、快照和错误可以通过运行 ID 查询。

## 3. 非功能需求

- 本地无外部服务依赖即可启动核心系统。
- 数据库文件可以复制、备份和恢复；恢复前必须验证迁移和规范化投影，验证失败不得替换当前库。
- API 错误结构统一，不能用 500 掩盖参数错误或业务冲突。
- 核心领域模块不得依赖 HTTP、前端和具体数据库。
- 同一确定性输入、版本和 seed 可以重复产生一致的规范化报告。
- 本地服务默认绑定 `127.0.0.1`，不向局域网暴露管理端口。
- 关键输入不能通过日志泄露到无关输出。

## 4. 数据口径

系统产生的数据身份必须显式区分：

- `ENGINE_RUNTIME_RESULT`：柔性引擎实际执行产生的运行结果。
- `ENGINE_EXPERIMENT_RESULT`：基于固定配置和版本执行的工程验证结果。
- `DERIVED_METRIC`：从引擎运行或验证结果计算出的派生指标。
- `EXTERNAL_REFERENCE`：仅作为论文背景或对比说明的外部资料。
- `SIMULATED_ONLY`：只用于演示或测试界面的合成数据。
- `UNKNOWN`：当前无法判断来源或真实性。

任何没有运行证据的数字不得进入正式论文实验结果；平台运行结果不得改写为外部业务系统生产指标。

## 5. v0.3 验收基线

1. 干净检出后可执行 `mvn.cmd test`、`mvn.cmd package` 和前端 `npm.cmd run build`。
2. 可以从控制面创建自定义模型、Schema、工作流和本体关系。
3. 可以执行至少两步连续状态迁移，并在重启后继续。
4. 失败输入不会推进状态，重复幂等请求不会重复执行。
5. 每次运行可以查到输入、输出、快照、Trace 和错误。
6. 20 条契约回归仍然可以独立执行，且结果与引擎状态分离。
7. 所有新增能力有自动化测试和文档，不依赖原始源码。
