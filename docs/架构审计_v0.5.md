# 架构审计 v0.5

更新时间：2026-09-02

## 审稿结论

v0.4 已经封住了控制面 DTO 可变性、受控写入、HTTP revision 条件和 SQLite 语义投影断链。本轮继续检查后，剩余最明显的审计缺口是：事件只有自然语言 `details`，审阅者无法稳定回答“哪个字段从什么值变成什么值”。这会让配置回放和论文复核依赖人工解释。

本轮将审计记录升级为追加、可解释的结构化字段差异事件，并把同一契约贯穿 JSON 兼容层、SQLite 规范化表、重启加载和坏数据拒绝。当前仍可接受为论文级、单机/本地 Provider 研究实现，不将其扩大解释为远程服务治理或生产级高可用系统。

## 发现与处置

| 严重度 | 审计发现 | 根因 | 本轮处置 | 证据 |
| --- | --- | --- | --- | --- |
| P1 | 配置审计只有文本描述，无法机器化复核 before/after | `AuditEventRecord` 没有字段级差异模型，SQLite 只保存 details | 新增 `AuditChangeRecord(path, beforeValue, afterValue)`；模型、Schema、Workflow、本体、服务更新均写结构化 changes | `auditEventsCarryTheStateRevisionTheyBelongTo`、`ontologyAndProviderChangesUseAuditedCommands` |
| P1 | 运行回滚只能证明“发生过”，不能直接看到状态和值如何变化 | 回滚审计没有记录上下文状态和值 | 回滚事件记录 `context.state`、`context.status`、`context.values` 的 before/after | `passedRunCanBeRolledBackOnlyAtTheLatestContextRevision` |
| P1 | 审计差异在 SQLite 升级或人工篡改后可能被静默覆盖 | 旧表没有 changes 列，加载流程没有结构校验 | SQLite v8 增加 `changes_json`；JSON 形状或 path 非法时加载失败，不回写兼容 payload | `persistsEngineStateAcrossRepositoryReload`、`rejectsMalformedAuditChangeSetBeforeRewritingCompatibilityPayload` |
| P2 | 重复的 PUT 命令也会制造无意义 revision 和审计噪音 | 配置更新命令未区分 no-op 与真实变更 | 关系/服务更新在无差异时直接返回，不递增 revision、不追加审计 | `repeatingAnIdenticalConfigurationCommandIsIdempotent` |
| P1 | 直接覆盖当前 SQLite 文件可能把坏备份带入运行态 | 恢复流程没有预校验和替换边界 | `restoreFrom` 先迁移并加载临时副本，全部校验通过后才原子替换；坏备份保留原库 | `restoresOnlyAValidatedBackupAndLeavesLiveDatabaseUntouchedOnFailure` |

## 变更契约

```json
{
  "path": "schema.fields[score]",
  "beforeValue": null,
  "afterValue": {
    "type": "INTEGER",
    "required": false,
    "version": 2,
    "defaultValue": null
  }
}
```

`path` 是控制面定义的稳定字段路径，不是 Java 反射路径；值必须保持 JSON-compatible。事件仍然保留 `details` 作为人类可读摘要，`beforeRevision/afterRevision` 负责写入归属，三者职责不同，不能互相替代。

## 数据与版本边界

- JSON 状态中的旧审计事件没有 `changes` 时按空数组兼容读取；旧的 `beforeRevision/afterRevision=0/0` 也保留兼容语义。
- SQLite v8 将差异数组存入 `audit_event.changes_json`，与 revision 链在同一事务中保存。
- SQLite 加载先完成投影完整性检查，再从规范化表重建；差异 JSON 解码失败时不会把坏表反向写回 `engine_state.payload_json`。
- 配置更新命令对真实变化递增 revision，对重复相同请求保持幂等；这仍是单机乐观并发语义，不是分布式锁。

## 验收结果

- Engine Admin：32 个 Service 测试、4 个 HTTP 测试全部通过。
- SQLite：12 个测试全部通过，包含审计差异持久化、损坏差异拒绝、历史运行保留和备份恢复完整性用例。
- 全工程：74/74 Maven 测试通过；clean package、smoke、契约 20/20、前端生产构建和只读项目状态审计已执行。仓库内历史 SQLite/JSON 产物若存在 stale/legacy 状态必须报告 WARN，不通过改写历史数据制造 PASS。
