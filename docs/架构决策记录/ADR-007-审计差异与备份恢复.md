# ADR-007：结构化审计差异与校验后备份恢复

日期：2026-09-02
状态：Accepted

## 背景

仅保存审计事件的自然语言摘要，无法稳定支持配置回放、机器化审阅和论文复核；仅复制或直接覆盖 SQLite 文件，也无法证明恢复文件仍满足当前 Schema、Workflow、运行关联和外键约束。

## 决策

1. `AuditEventRecord` 继续保留人类可读的 `details`，同时追加 `AuditChangeRecord` 列表。每条差异包含稳定的控制面 `path`、`beforeValue` 和 `afterValue`，值限定为 JSON-compatible 对象。
2. revision 链表示一次状态写入的归属；changes 表示该事件影响的内容。两者分别校验，不以文本摘要代替任一语义。
3. JSON 兼容层对历史缺失的 changes 按空数组读取；SQLite v8 使用 `audit_event.changes_json` 保存差异，并在加载阶段拒绝非法 JSON 或空字段路径。
4. SQLite 备份操作与同一 Repository 串行化；恢复先复制到目标目录的临时文件，使用完整迁移、规范化投影和外键检查加载验证，成功后才执行原子替换。验证失败不得触碰当前数据库。
5. 关系和服务的重复相同更新是 no-op，不产生无意义 revision 或审计事件。

## 后果

- 审计消费者可以在不解析自然语言的情况下得到确定性的配置差异。
- 旧状态可以继续加载，但旧审计记录的空 changes 不会被伪造回填。
- 单机文件级恢复具备可验证的安全边界；这不等同于跨主机灾备、在线热备、多实例协调或分布式一致性。
- 配置/Schema 回滚、字段路径的跨版本语义解释和论文格式化导出仍由上层策略负责。
