# ADR-005：Schema 演进与运行时上下文迁移

日期：2026-09-02
状态：Accepted

## 背景

Schema 是不可变版本集合，而 `RuntimeContext` 会跨多个请求持续存在。模型发布新版本后，旧上下文不能直接被当前版本的字段校验覆盖，否则新增字段、删除字段和历史字段值会混杂在同一次运行中，导致运行结果无法解释。

## 决策

1. 运行开始时，以模型当前 Schema 版本作为执行目标；上下文仍保留自己的历史 Schema 版本。
2. 上下文版本落后时，执行视图只保留目标版本中的同名字段；目标字段缺失且存在默认值时注入默认值；目标版本不存在默认值的必填字段继续交给校验器判定。
3. 不对字段类型变化做隐式转换。类型不兼容必须形成可解释的校验失败，不能为了让流程通过而篡改历史值。
4. before Snapshot 记录上下文原始版本和值，after Snapshot 记录当前执行版本和值；只有运行成功时才把迁移后的值和目标版本提交回上下文。
5. 迁移过程通过校验 Span 的 `schemaFromVersion`、`schemaToVersion` 和 `schemaMigrationApplied` 属性进入 Trace，保证论文实验可复核。

## 后果

- 新增带默认值的字段可以安全作用于存量上下文，且上下文只在成功运行后升级版本。
- 被当前 Schema 删除的旧字段不会继续污染目标版本；失败运行不会推进上下文。
- 字段改名通过 `schema_migration` 显式记录并可跨版本链恢复；跨类型转换和人工版本回滚仍需后续策略，当前实现不会猜测语义。
