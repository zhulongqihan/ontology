# ADR-001：采用领域—应用—基础设施—接口分层

日期：2026-09-02
状态：Accepted

## 背景

当前 v0.2 将管理路由、状态仓库和运行逻辑集中在 `EngineAdminService` 与 `EngineAdminServer`。继续在这个结构上增加迁移、回滚、审计和 Trace 会形成难以测试的高耦合模块。

## 决策

保留现有模块作为兼容基线，逐步增加以下分层：

1. Domain：纯 Java 领域规则。
2. Application：运行用例和事务边界。
3. Infrastructure：SQLite、JSON、文件和时间/ID实现。
4. Interface：HTTP API 和 CLI。
5. Frontend：只通过 API 操作引擎，不直接读取数据库。
6. Experiment：独立调用引擎并产生证据。

不直接替换为大型 Web 框架。当前 JDK HttpServer 足以支持本地复现，先解决领域和数据一致性问题；只有当接口需求超过当前边界时才评估框架迁移。

## 后果

- 核心可以独立测试和复用。
- 持久化可以从 JSON 平滑迁移到 SQLite。
- API 可以保留旧路由并增加 `/api/v1`。
- 迁移期间会同时存在旧的管理服务和新的应用服务，需要明确弃用时间。
