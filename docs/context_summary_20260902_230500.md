## 已确认的根因级缺口

1. OntologyType 目前没有真正的版本/定义 hash，Run 仅记录 ontologyTypeId；模型绑定虽为显式绑定，但版本语义未闭合。
2. SQLite 写入前把 Trace 标记为 COMMITTED；这把“数据库提交”“提交后生命周期标记”“客户端收到/渲染”混在一起。应改为真实的提交后标记，并诚实处理崩溃窗口。
3. SQLite 缺少充分的坏 Snapshot hash、坏 Trace lifecycle、运行时 ontology 版本/定义一致性校验；此前临时副本实测坏 snapshot/lifecycle 可以被启动和读取接受。
4. SQLite 并发协议只有 revision 检查，缺少明确的 busy timeout/retry 与针对独立实例的稳定验证。
5. Runtime 有 retry/rollback，但没有面向原始输入的 replay API/持久化关系。
6. A/B/C 实验基线偏弱：A 是名称派生字符串比较而非独立 baseline 实现；B 主要是 JSON 失败注入；C 未重启验证且 seed 未改变执行顺序；suite 产物缺少完整 manifest/per-case evidence。
7. Contract 结果报告在相同 seed 下稳定，但 trace hash 因时间戳不同而不稳定；只能声称报告/结果稳定，不能声称完整证据 hash 稳定。
8. 当前论文和若干 docs 存在过时或过强表述：74/74、Trace 提交前后语义、原系统兼容/等价暗示，以及把局部工程组合包装成理论创新的风险。
9. 前端真实消费后端状态，但 add model 类型不含 ontologyTypeId，API 客户端没有读取/携带 ETag/If-Match，开发代理地址依赖硬编码默认值，缺少 replay UI 和前端自动化入口。
