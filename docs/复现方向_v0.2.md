# 柔性引擎复现方向 v0.2

更新时间：2026-09-02

当前工程需求入口：`docs/系统需求规格_v0.3.md`；本文作为产品方向摘要，详细领域术语和架构决策见同目录 v0.3 文档。

## 一、总目标

本项目的主目标是复现一个可以提交源码、可本地运行、可继续配置的柔性引擎。后台管理平台是引擎的控制面，用来注册和修改模型定义；它不是独立的演示页面，也不是把实验数据静态贴到页面上。

引擎复现的核心闭环是：

`模型注册 → 动态 Schema → 运行时校验 → 事件驱动状态迁移 → 本体关系配置 → 运行快照持久化`

## 二、当前交付边界

已经可以运行的核心行为：

1. 注册柔性对象模型，配置初始状态。
2. 追加动态字段，支持 STRING、INTEGER、DECIMAL、BOOLEAN、JSON、OBJECT，并递增 Schema 版本。
3. 追加工作流事件转换；非法事件和非法字段输入会形成失败运行，不会被写成成功。
4. 注册本体类型、固定属性、动态属性和对象关系。
5. 注册本地 Provider/Assembler 服务地址，明确使用 `local://`，不伪装生产依赖。
6. 通过 `contextId` 复用上次运行快照的字段和状态，实现跨请求连续迁移。
7. 将模型配置和运行历史写入 `data/engine-state.json`，重启后重新加载。
8. 通过中文后台控制面完成以上配置和运行操作。

## 三、系统边界

`flexible-engine-core` 是行为内核；`ontology-core` 是本体对象和关系模型；`compatibility-adapter` 是本地 Provider/Consumer 兼容层；`engine-admin-api` 是控制面和运行时入口；`reproduction-app` 是启动入口；`experiment-runner` 只负责契约回归和结果产物。

没有原始源码、生产注册中心和生产数据库时，本项目只声明“复现系统的运行结果”，不声明原系统的生产指标。原论文中缺少原始证据的数字不能通过本项目自动升级为原系统事实。

## 四、当前明确限制

- MVP 采用 JSON 文件持久化，尚未引入数据库事务和并发版本控制。
- 管理面当前以新增配置为主，暂未提供模型/字段/关系的删除和编辑接口。
- Trace 当前记录 Trace ID 和总耗时，尚未拆分为多 span 的请求—响应—服务调用时间线。
- 契约实验运行器与后台运行状态是两条用途不同的链路，后续可以增加统一导入，但不能将两者的结果混写。

## 五、下一阶段验收重点

下一阶段必须围绕引擎行为继续扩展，而不是回到静态实验工作台：Schema 迁移规则管理、运行回滚/重试/幂等、完整 Trace span、关系装配运行和兼容服务调用链。每一项都要有代码、测试和可重复运行输出。
