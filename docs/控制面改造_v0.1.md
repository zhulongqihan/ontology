# 引擎控制面改造 v0.1

## 目标

本轮将前端产品形态从“资源菜单集合”推进为以引擎控制面为主的可复核工作台。控制面负责引导 Model、Ontology、Schema、Workflow 和真实 Run 的连续操作；知识图谱和成对运行页面作为辅助分析入口。

## 已实现

- 总览页新增“从定义到证据”任务路径：定义模型、绑定本体、真实运行、复核结果。
- 新增独立知识图谱页面，区分 `OntologyTypeConfig` 静态定义和 `RuntimeRun.ontologyGraph` 运行时图谱。
- 图谱展示对象节点、关系方向、基数、root object、节点属性数量和来源身份。
- 图谱关系目标使用大小写不敏感的 canonical ID 归一化，避免 `subject`/`Subject` 被错误展示为两个节点。
- 新增成对运行观察页面，读取两个真实 Run 的 Run、Trace 和 Snapshot，展示状态、最终状态、耗时、Span 数、Snapshot 数和本体版本/hash。
- 新增调用链 Waterfall、结构化 Decision Evidence 和运行时图谱摘要。
- 页面在输入条件不一致时明确标记 `UNPAIRED`；输入一致时仍只标记为 `PAIRED OBSERVATION`。
- 页面明确说明当前两侧均为柔性引擎真实 Run，不能把观察结果写成固定基线 Before/After 提升。

## 当前证据边界

- 本轮没有修改后端运行语义、SQLite schema 或历史数据。
- 当前后端尚未接入可执行的 `Rigid Mapping Baseline`，因此成对运行页是证据观察工具，不是竞争基线实验器。
- 页面中的 Decision Evidence 是可复核的结构化规则/运行证据，不是原始模型 COT。
- 远程 Provider、分布式运行、权限、多租户和生产业务收益不在本轮范围内。

## 验证方式

- `frontend` 生产构建必须通过。
- Playwright 真实浏览器检查总览、知识图谱、运行时图谱和成对运行页面。
- 静态图谱检查关系目标不产生重复节点。
- 使用临时 SQLite 创建两次相同输入的真实 Run，确认页面读取真实 API 数据并显示成对条件。
- 390px 视口检查文档宽度不超过客户端宽度。
