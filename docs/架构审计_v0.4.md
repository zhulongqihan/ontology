# 架构审计 v0.4

更新时间：2026-09-02

## 审稿结论

在本轮改造前，系统已经具备可运行的 Schema、Workflow、本体装配、Provider Trace 和 SQLite 投影，但还不能以“控制面边界清晰、配置可审计、运行可关联、持久化可拒绝坏数据”的标准通过架构审查。主要问题不是缺少页面，而是聚合对象、写入命令、HTTP 协议和规范化投影之间存在可绕过的边界。

本轮已针对这些根因完成跨模块修复。当前可以接受为论文级、单机/本地 Provider 研究实现；不能据此声称已经具备远程服务治理、认证授权或生产级高可用能力。

## 发现与处置

| 严重度 | 审计发现 | 根因 | 本轮处置 | 证据 |
| --- | --- | --- | --- | --- |
| P0 | 公开读取结果可反向修改内部状态 | Service 返回浅拷贝，嵌套列表和 Map 仍指向聚合内部 | 所有管理读取、运行结果、快照、Trace、审计和幂等记录改为深拷贝；内部使用 `modelRef/runRef/contextRef` | `publicReadModelsAreDetachedFromTheMutableAggregate` |
| P0 | 本体关系、Provider 状态只能靠外部直接改 DTO | 缺少正式更新命令，测试曾直接操作 getter 返回值 | 增加 `updateOntologyRelation`、`updateService`，均校验、审计、递增 revision、事务保存 | `ontologyAndProviderChangesUseAuditedCommands` |
| P1 | HTTP 错误无法关联请求，且泄漏内部异常文本 | 错误响应只有一个 `error` 字段，没有请求级 correlation id | 统一 `errorCode/message/traceId`，返回 `X-Trace-Id`；内部错误使用稳定外部消息 | `httpConfigurationUpdatesAndErrorsHaveStableContracts` |
| P1 | HTTP 配置写入没有可用的版本条件 | revision 只存在于仓库，客户端没有 ETag/If-Match 协议 | 所有响应返回 `ETag`；带 `If-Match` 的写入在同一 Service 锁内校验，过期返回 409；审计事件记录 before/after revision | `httpConfigurationUpdatesAndErrorsHaveStableContracts` |
| P1 | 迁移规则可能跨版本误匹配 | 仅按目标版本和目标字段查找规则 | 要求 `fromVersion = toVersion - 1`，同一目标出现多个规则时拒绝 | `migrateContextValues` 相邻版本约束 |
| P1 | SQLite 外键通过但语义投影可能已坏；极短 Span 的时间排序不稳定 | 缺少版本连续性、Trace/Run、Snapshot/Context、迁移字段一致性校验，且没有显式 Span 顺序 | 加载前执行版本链、字段版本、迁移源/目标、Trace 绑定、Context 最后运行和快照归属校验；SQLite v6 增加 `span_index`；坏投影不再回写 | `rejectsAFieldVersionThatCannotBelongToItsSchema`、`rejectsRuntimeRunWithMismatchedTraceIdentity` |
| P1 | 首次建库和后续 Admin 写入的配置投影不一致 | 默认 seed 只含当前版本，依赖后续 normalize | seed 直接携带完整 Schema/Workflow 历史，裸仓库读取与 AdminService 使用同一契约 | `readsConfigurationFromNormalizedTablesBeforeCompatibilityPayload` |

## 当前边界

```text
HTTP request
  └─ X-Trace-Id / If-Match
      └─ EngineAdminServer
          └─ EngineAdminService（深拷贝 API 边界 + 受控写命令）
              ├─ EngineRuntimeService（版本绑定、迁移、运行提交）
              ├─ LocalOntologyProvider（当前仅 IN_PROCESS）
              └─ EngineStateRepository
                  ├─ JSON：兼容/迁移入口
                  └─ SQLite：规范化配置与运行投影、事务、加载前完整性闸门
```

这里的 `ETag/If-Match` 是单机状态 revision 的乐观并发协议，不是分布式锁；Provider Trace 是本地 JVM 内调用，不是网络链路。论文实验应明确写出这两个边界。

## 验收结果

- 管理服务测试：27 个 Service 测试、3 个 HTTP 测试全部通过。
- SQLite 测试：9 个测试全部通过，包含两个故意破坏规范化表的拒绝用例；SQLite v7 保存审计 revision 链。
- 全工程仍需以根目录 `mvn test`、`mvn package`、契约 20/20 和前端生产构建作为最终门禁。

## 仍需后续研究

以下不是本轮被掩盖的缺陷，而是明确的下一阶段边界：跨进程 Provider/RPC 及 trace context 传播、认证授权、配置差异级审计字段、故障注入与可配置重试、Schema 回滚、论文格式化导出，以及多实例数据库并发和备份恢复演练。
