- 独立 Java/Maven 多模块工程。
- Java 8 兼容语法目标，可在当前 JDK 17 上构建。
- 柔性字段定义、动态记录、字段校验。
- 工作流状态、事件转换、非法事件拒绝。
- 上下文快照和稳定 SHA-256。
- schema 版本迁移、字段改名和默认值。
- 运行时旧上下文向当前 Schema 的同名字段迁移、默认值注入和版本边界快照。
- Questionnaire、Subject、Option、OntologyRelation。
- `JobOntologyDetail` 的固定属性、动态属性和关系。
- 本地 Questionnaire Provider/Consumer 兼容层。
- 20 条契约规格文件。
- 20 条契约代码执行器。
- 每个用例的 request/response/trace/result JSON。
- 可独立运行的 fat jar。
- `engine-admin-api` 管理模块与状态仓库接口；`engine-persistence` 提供 SQLite 事务仓库和旧 JSON 迁移。
- 模型注册、动态字段写入、Schema 版本递增、状态转换写入。
- 本体类型、对象关系和本地服务注册写入。
- 管理 API 的运行执行入口：Schema 校验、事件状态迁移、运行快照和 Trace ID。
- 运行应用服务已从 `EngineAdminService` 拆出：固定 Schema/Workflow 版本，独立 RuntimeContext，失败不提交上下文。
- 运行记录已增加 before/after Snapshot、稳定 SHA-256、错误码、幂等键、上下文 revision 和不可变 Trace Span 集合。
- SQLite 迁移 v2/v3 已建立运行域规范化表，并在同一事务内同步运行、快照、Trace、Span、审计、幂等、重试和回滚投影；旧 JSON 仍仅作为迁移/备份入口。
- HTTP 已支持 Run、Trace、RuntimeContext 和 AuditEvent 查询；业务并发冲突返回 409。
- 失败 Run 已支持创建新的 attempt 重试；成功 Run 已支持基于最新上下文 revision 的可审计回滚，并同步 SQLite v3 运行投影。
- SQLite 迁移 v4/v5 已建立配置域规范化表和 Schema 改名迁移表：模型、Schema 版本/字段/迁移、Workflow 版本/转换、本体类型/属性/关系和服务注册，并与状态写入放在同一事务投影。
- Schema 演进支持字段新增、显式改名和删除；旧上下文按版本链迁移，类型变化不做隐式转换。
- 本体执行已接入统一图校验：对象类型、固定/动态属性、关系来源和目标类型、重复对象/关系及 `1:1`/`1:N` 基数均在运行时检查；Questionnaire → Subject → Option 链路生成动态派生属性。
- Provider 观测已接入运行证据：本地 `ontology-assembler` Provider 通过注册服务边界执行，Trace 的 Provider Span 保存服务元数据、请求 JSON、响应 JSON、失败原因和真实耗时；未请求本体或前置阶段失败时记录 `SKIPPED` 及原因，不伪造调用成功。
- 契约实验 Trace 已改为由真实 Provider/Consumer 调用前后的时间点生成，使用核心 Trace/TraceSpan 封存后序列化；报告 JSON 的稳定哈希与每次运行测得的 Trace 哈希分开解释。
- 控制面已提供运行快照、Trace、审计、幂等记录和完整 JSON 导出查询；前端证据中心支持选择运行、查看版本绑定、重试/回滚和导出。
- 连续运行上下文：复用 `contextId` 时从上一快照状态继续，并合并动态字段。
- React/Vite 中文柔性引擎后台控制面：引擎总览、模型管理、Schema/字段、工作流、本体模型、服务注册、运行调试。
- 前端响应式布局、状态标签、数据身份标识、API 断连状态和写入反馈。
- 控制面聚合边界已收紧：公开读取结果全部深拷贝，不能通过嵌套 getter 绕过审计、版本和持久化；本体关系与服务注册改为显式更新命令。
- HTTP 错误已统一为 `errorCode/message/traceId`，同时返回 `X-Trace-Id`；响应暴露 `ETag`，配置写入支持 `If-Match` revision 条件。
- SQLite 加载前完整性闸门已覆盖 Schema/Workflow 连续版本、字段版本、相邻迁移、Run/Trace、Snapshot/Context 归属关系；SQLite v6 为 Trace Span 增加显式顺序号，默认 seed 直接包含完整配置历史。
- 配置和运行审计事件已携带 `beforeRevision/afterRevision` 及结构化 `changes[{path,beforeValue,afterValue}]`，SQLite v8 将其纳入规范化投影和加载前校验；重复相同配置命令保持 no-op；SQLite 备份恢复先校验临时副本再原子替换。

## 数据口径

`runs/contract-20` 下的产物只有在对应 `manifest.json` 的 source revision、seed 和 `data_identity` 经本轮重新生成并核对后，才可作为本轮 `ENGINE_EXPERIMENT_RESULT` 证据；历史目录可能包含旧 identity，不能直接复用。无论哪一版都不是外部生产系统数据，也不是手工填写的模拟结果。

当前前端直接消费 `engine-admin-api` 的运行状态，不再使用静态 `frontend/src/data.ts` 展示快照。新管理 API 产生的运行结果是本柔性引擎的真实运行结果，身份标记为 `ENGINE_RUNTIME_RESULT`；契约验证报告使用 `ENGINE_EXPERIMENT_RESULT`，并以重新执行后 `runs/contract-20` 中带哈希的运行产物为准。旧运行记录若缺少版本、快照或 Span，只作为历史存档，不能用于证明本轮能力。
